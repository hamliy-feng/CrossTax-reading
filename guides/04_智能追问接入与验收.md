# 智能追问接入与验收

承接 `research/handoffs/2026-10-06_CrossTax_智能追问推荐_独立决策模型_执行方案.md`，不采用付费 JEV。本期代码在 `web/workbench.py` 和 `web/workbench-extension.js`。

## 消息、账号和项目接入

推荐绑定 `case_id` 与服务器 UUID `message_id`，不再根据消息数组位置推断。必须是当前 active_leaf、assistant、status=complete；主回答成功保存之后才调用独立推荐请求。旧消息迁移时建立稳定 ID 和 parent_id 链，不能反复生成 ID。

owner_id 从已验证的 Neon 会话或游客 Cookie 推导。项目归属在对话上；迁移游客时推荐、工具、文件和对话一起迁移。不同 owner 无法跨账户查询推荐。项目汇总输出与推荐分别保存。

## 配置与请求

默认 `enabled=false`、`provider=deepseek`、独立模型默认采用项目当前 DeepSeek ID、count=3；允许 0–4。服务商来自现有白名单，不接受任意 API Base URL。

```json
POST /api/recommendations/settings
{"enabled": true, "provider": "deepseek", "model": "deepseek-flash", "count": 3}

POST /api/recommendations/generate
{"case_id": 123, "message_id": "服务器生成的 UUID"}
```

Key 优先级：本浏览器独立推荐设置 → 同服务商主聊天 Key → 服务端默认环境变量。Key 仅进程内存在，不进入数据库、网页响应、日志或公开包。非秘密模型设置持久保存，可跨设备读取。

独立请求只提供必要事实和最近当前分支；模型返回 `{"questions":["问题"]}`。服务端检查类型、长度、去重和上限，超时十秒或格式错误返回空推荐，不影响主回答。推荐按消息内容、事实、分支和配置的 SHA 指纹缓存；成功缓存不重复调用。

界面推荐仅在同一会话且仍选中同一答复时展示；切换会话丢弃迟到显示。点击沿用正常发送流程，发送期间禁用重复点击；不自动生成下一条聊天。事实或配置变化重新生成指纹，旧推荐仍可追溯。

## 保存与内部记录

`crosstax_app.records` 的 preferences 保存开关/模型/数量，recommendation 保存问题列表、message_id、case_id、输入 SHA、实际模型、使用量和结果。消息本体由服务器保留；编辑/重生成新增分支，不覆盖旧推荐输入。

外部 UI 不显示“AI 核验”等标签；推荐文字不追加答复末尾提示。主答复和导出由统一 finalize 函数处理，仅追加一次约定提示。

## 验收

- 默认关闭：真实推荐调用为零。
- 主回答失败、停止、只有部分输出：推荐调用为零。
- 独立模型切换不改变主模型；Key 不在 GET 设置、SQLite/PostgreSQL payload 和浏览器日志出现。
- 结构化输出缺失、空数组、超四条、重复或长问题时可靠处理。
- 同一指纹第二次请求命中缓存；输入事实、分支或推荐配置改变后产生新指纹。
- 切换会话不串推荐；点击一次生成一个新用户消息；当前忙时不能重复发送。
- 游客迁移后记录可读，另一账号查询同编号返回不存在。
- 保存先于推荐生成；网页关闭不影响已保存主回答。

自动测试和真实 DeepSeek 请求分别记录，模拟结果不能计为已调用服务商。并发重复生成及失败缓存的重试行为要单独验收并在实际报告中注明。

AI 可能会说错，请注意甄别。
